# 3.4.2. Bracket Validation

## 📋 Overview
This C program checks whether a string of brackets is valid (balanced). A string is valid if every opening bracket `(`, `{`, `[` has a corresponding closing bracket `)`, `}`, `]` in the correct order. The program uses a character stack to track unmatched opening brackets and prints `"true"` or `"false"` accordingly.

## 🎯 Purpose
The purpose of this program is to solve the classic bracket validation problem using a stack. This problem is a common application of the stack data structure and is frequently encountered in compilers, editors, and programming contests.

## ✨ Key Features
* Stack-based bracket validation using a character array
* Handles all three bracket types: `()`, `{}`, `[]`
* Returns `true` for valid (balanced) bracket strings and `false` for invalid ones
* Handles edge cases like empty stacks on closing brackets and leftover unmatched brackets

## 🏗️ Data Structures Used
* **Array-based Stack**: A global character array `stack[MAX_STACK_SIZE]` (size 10000) with a `top` index to simulate a stack for bracket tracking.

## 🔧 Implementation Details

### Algorithm Explanation
1. Reset `top = -1` at the start of each `isValid()` call.
2. Iterate through each character of the input string:
   - If it is an opening bracket (`(`, `{`, `[`), push it onto the stack.
   - If it is a closing bracket:
     - If the stack is empty, return `false` (unmatched closing bracket).
     - If the top of the stack matches the corresponding opening bracket, pop it.
     - Otherwise, leave the unmatched bracket (current implementation does not return `false` here — this is a known limitation).
3. After the loop, return `true` if the stack is empty (all brackets matched), `false` otherwise.

### Functions Documentation
- **`isEmpty()`**
  - **Purpose**: Checks if the stack is empty.
  - **Returns**: `1` (true) if empty, `0` (false) otherwise.

- **`push(char i)`**
  - **Purpose**: Pushes a character onto the stack.
  - **Parameters**: `i` — character to push.
  - **Returns**: `void`.

- **`getTop()`**
  - **Purpose**: Returns the top character without removing it.
  - **Returns**: `char` — top element, or `'a'` if empty (with error message).

- **`pop()`**
  - **Purpose**: Removes the top element from the stack.
  - **Returns**: `void`.

- **`isValid(char *s)`**
  - **Purpose**: Validates whether the bracket string `s` is balanced.
  - **Parameters**: `s` — input string.
  - **Returns**: `int` — `1` (true) if valid, `0` (false) if invalid.

- **`main()`**
  - **Purpose**: Reads the input string and prints the validation result.
  - **Returns**: `int` (0 on success).

## 💻 Compilation & Usage

### Compilation
```bash
gcc "3.4.2. Bracket Validation.c" -o bracket_validation
```

### Running the Program
```bash
./bracket_validation
```

## 📥 Input/Output

### Input
* A single string of bracket characters (no spaces).

### Output
* `"true"` if the string is a valid balanced bracket sequence.
* `"false"` otherwise.

## 📊 Complexity Analysis
- **Time Complexity**: O(n) — each character is processed once.
- **Space Complexity**: O(n) — stack can hold up to `n` characters.

## 🧪 Example Run
```
{[()]}
true
```
```
{[(])}
false
```

## ⚠️ Edge Cases & Error Handling
* Handles empty stack when a closing bracket is encountered (returns `false`).
* Does not return `false` for a mismatched pair (e.g., `{]`) — this is a known bug in the current implementation; the `else` branch inside the closing-bracket handling is incomplete.

## 🚧 Limitations
* The mismatched-pair case (e.g., `{]`) is not correctly handled; the `else` branch should return `false` but currently does nothing.
* Fixed maximum string length of `MAX_STACK_SIZE` (10000).

## 📝 Notes
This program is for educational purposes. The bug in mismatched-pair handling can be fixed by adding `return false;` in the final `else` branch inside `isValid()`.
